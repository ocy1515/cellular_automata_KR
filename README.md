# 셀룰러 오토마타 실험실

> 색 상태와 주변 8칸을 보고 움직이는 **개미(ant)** 를 직접 만든 규칙으로 시뮬레이션하는 HTML 도구입니다.

랭턴의 개미를 확장한 형태로, 한 줄에 규칙 하나씩 적으면 개미가 그 규칙대로 격자 위를 움직이며 칸의 색을 바꿉니다.

문법 설명은 `index.html` 파일 안에서도 확인할 수 있습니다.

### 2. 규칙 문법

#### 2.1 전체 구성

규칙 코드는 한 줄에 명령 하나씩 쓰는 텍스트입니다. 줄은 다음 네 종류 중 하나입니다.

| 종류 | 형식 | 역할 |
| --- | --- | --- |
| 색 지정 | `setcolor (기호)=(#RRGGBB)` | 상태 기호에 색을 지정 |
| 배경 상태 | `setbg (기호)` | 격자 전체의 시작 상태 |
| 시작 칸 상태 | `setstart (기호)` | 개미가 처음 서 있는 칸의 상태 |
| 규칙 | `(조건) -> (명령)` | 조건이 맞으면 명령 실행 |

- 빈 줄은 무시됩니다.
- `#` 또는 `//`로 시작하는 줄은 주석입니다.
- 대소문자는 구분하지 않습니다. (`a`와 `A`는 같은 상태입니다.)

#### 2.2 상태 기호와 색 — `setcolor`

```text
setcolor B=#0000FF
```

- **상태 기호**: `A`–`Z` 중 하나 또는 `0`–`9` 중 하나. 칸의 "색 상태"를 구분하는 이름입니다.
- **색**: `#RRGGBB` 형식의 16진수 색상 코드.
- 같은 기호에 `setcolor`를 두 번 쓸 수 없습니다.
- `setcolor`를 쓰지 않은 기호는 아래 기본 색을 씁니다.

| 기호 | A | B | C | D | E | F |
| --- | --- | --- | --- | --- | --- | --- |
| 기본 색 | `#F0F2F5` | `#252B38` | `#F2B84B` | `#8B7CF6` | `#E56C8A` | `#4AA8D8` |

| 기호 | G | H | I | J | K | L |
| --- | --- | --- | --- | --- | --- | --- |
| 기본 색 | `#72C58B` | `#E58B50` | `#E5C7A9` | `#9ED7C7` | `#D7A8EF` | `#A8B8D8` |

M 이후의 기호는 위 12색이 반복됩니다.

#### 2.3 칸 위치 번호

조건에 쓰는 위치 번호는 **화면 기준으로 고정**됩니다. 개미가 어느 쪽을 보고 있어도 번호는 바뀌지 않습니다.

```text
[2][3][4]
[5][1][6]
[8][7][9]
```

`1`은 개미가 서 있는 칸이고, `3`은 화면 위쪽(북쪽) 칸, `6`은 오른쪽(동쪽) 칸입니다.

#### 2.4 조건

```text
ant_cell_(위치)=(상태)
```

예: `ant_cell_1=A` — 개미가 서 있는 칸이 A 상태일 때

- `&`로 여러 조건을 동시에 요구할 수 있습니다.
  예: `ant_cell_1=A & ant_cell_3=B` — 현재 칸이 A **이고** 북쪽 칸이 B일 때
- 여러 규칙의 조건이 동시에 성립하면 **먼저 작성된 규칙 하나만** 실행합니다. 구체적인 조건을 위에, 일반적인 조건을 아래에 쓰세요.
- 조건이 완전히 같은 규칙을 두 번 쓸 수 없습니다.
- 조건은 그 단계가 시작될 때의 격자를 기준으로 검사합니다. 같은 줄의 명령이 칠한 색은 그 단계의 조건 판정에 영향을 주지 않습니다.
- 경계 처리가 "끊김"일 때 격자 밖의 칸은 어떤 상태와도 일치하지 않습니다. "이어짐"이면 반대편 칸을 읽습니다.

#### 2.5 명령

**이동 명령**

| 명령 | 동작 |
| --- | --- |
| `straight` | 현재 보는 방향으로 한 칸 이동 |
| `right` | 오른쪽으로 90도 회전한 뒤 한 칸 이동 |
| `left` | 왼쪽으로 90도 회전한 뒤 한 칸 이동 |
| `flip` | 180도 회전한 뒤 한 칸 이동 |

- 뒤에 `_n`을 붙이면 `n`칸 이동합니다. (`straight_2`, `left_3`처럼, `n`은 1~1000)
- 회전은 처음 한 번만 하고, 그 방향으로 `n`칸을 계속 이동합니다.

**칠하기 명령**

| 명령 | 동작 |
| --- | --- |
| `paint (상태)` | 그 시점에 개미가 서 있는 칸을 해당 상태로 변경 |
| `paint_prev (상태)` | 가장 최근 이동 명령이 **시작되기 전**에 개미가 있던 칸을 해당 상태로 변경 |

같은 줄에서 아직 이동 명령이 없었다면 `paint_prev`는 직전 단계에서 이동을 시작한 칸을 가리킵니다.

**명령 연결**

`;`로 여러 명령을 이어 쓰면 **왼쪽부터 순서대로** 실행됩니다.

```text
ant_cell_1=A -> right_2; paint_prev C
```

#### 2.6 규칙 작성 형식

```text
(조건) -> (명령)
```

```text
ant_cell_1=A & ant_cell_3=B -> left_2; paint_prev C
```

#### 2.7 여러 칸 이동과 규칙 검사 시점

- 여러 칸 이동 중 **지나가는 칸에서는 규칙을 검사하지 않습니다.**
- 이동이 모두 끝난 **도착 위치**에서 다음 단계의 규칙을 검사합니다.
- 따라서 `straight_5`로 지나간 중간 칸들은 아무 규칙도 실행되지 않고 색도 바뀌지 않습니다.

#### 2.8 배경 상태 — `setbg`

```text
setbg B
```

- 격자의 **모든 칸이 처음에 갖는 상태**를 정합니다.
- 한 번만 쓸 수 있고, 생략하면 `A`입니다.
- 배경 칸도 일반 칸과 똑같이 취급됩니다. 배경이 `A`이면 `ant_cell_1=A` 규칙이 배경 칸에서 그대로 실행됩니다. 배경에 해당하는 상태의 규칙이 없으면 실행 중에 오류가 납니다.
- 배경 상태의 색은 `setcolor`로 정한 색입니다. 범례에는 `A (배경)`처럼 표시됩니다.

#### 2.9 개미 시작 칸의 상태 — `setstart`

```text
setstart C
```

- 개미가 처음 서 있는 **칸 하나**의 상태를 정합니다.
- 한 번만 쓸 수 있고, 생략하면 배경 상태와 같습니다.

> [!NOTE]
> 배경과 시작 칸 설정이 다르면 **시작 칸 설정이 우선**합니다.
> 예: `setbg D` + `setstart A` → 개미가 선 칸은 A, 나머지는 모두 D

### 3. 화면 설정

#### 규칙 선택

- **자유 입력**: 직접 쓴 규칙을 적용합니다. **설명 보기** 버튼을 누르면 문법 설명이 팝업으로 열립니다.
- **예제**: 미리 준비된 규칙을 불러옵니다. 선택한 예제의 규칙이 아래에 표시되며, **이 예제를 자유 입력으로 복사**로 가져와 수정할 수 있습니다.
- 지금 시뮬레이션에 쓰이는 쪽(자유 입력/예제)의 섹션과 선택된 예제 버튼이 다른 색으로 강조됩니다.

#### 시뮬레이션 설정

| 항목 | 설명 |
| --- | --- |
| 격자 너비 / 높이 | 20~300칸. 개미는 격자의 중앙에서 시작합니다. |
| 속도 (단계/초) | 1~10000 |
| 경계 처리 | **경계에서 끊김**(기본): 개미가 가장자리를 넘으려 하면 멈춥니다.<br>**반대편으로 이어짐**: 반대편 가장자리로 넘어갑니다. |
| 시작 방향 | 북/동/남/서 |
| 페이지 배경색 | 페이지 바탕색. 브라우저에 저장되며, 격자 안의 색에는 영향이 없습니다. |

설정을 바꾸면 시뮬레이션이 초기화됩니다.

#### 조작 버튼

- **한 단계**: 규칙을 한 번 실행합니다.
- **100단계**: 규칙을 100번 실행합니다.
- **초기화**: 현재 규칙과 설정으로 처음부터 다시 시작합니다.
- **▶ 실행 / Ⅱ 일시 정지**: 연속 실행과 일시 정지를 전환합니다.

#### 표시 정보

단계 수, 개미 위치와 방향, 사용된 상태 개수가 위쪽에 표시되고, 아래쪽 범례에 상태별 색과 개미 표식(민트색)이 나옵니다.

### 4. 예제 모음

| 예제 | 설명 |
| --- | --- |
| 랭턴의 개미 | 가장 유명한 개미. 약 1만 단계 뒤 대각선 고속도로가 생깁니다. |
| RLR 개미 | 회전 방향을 바꾼 2색 개미 |
| 주변 감지 예제 | 북쪽 칸을 함께 검사하는 3색 규칙 |
| 5색 종합 예제 | 설명서의 예시. 직진하다 경계에서 멈추므로 경계 처리를 "이어짐"으로 바꿔 보세요. |
| 삼각형 성장 9색 | 어지럽게 퍼지다 큰 삼각형으로 자랍니다. 격자 200×200, 속도 3000으로 자동 설정됩니다. |

#### 직접 만들어 보기: 상태마다 도는 방향을 정하는 개미

상태마다 `left`/`right`를 정하고 다음 상태로 바꾸는 형태로 쓰면, 색이 여러 개인 개미를 쉽게 만들 수 있습니다.

```text
setcolor A=#0B0F1A
setcolor B=#1E3A8A
setcolor C=#2563EB

ant_cell_1=A -> left; paint_prev B
ant_cell_1=B -> right; paint_prev C
ant_cell_1=C -> right; paint_prev A
```

### 5. 자주 나는 오류

| 메시지 | 원인과 해결 |
| --- | --- |
| 일치하는 규칙이 없습니다 | 개미가 선 칸의 상태(또는 조건 조합)에 맞는 규칙이 없습니다. 배경 상태(`setbg`, 기본 A)의 규칙을 빠뜨리지 않았는지 확인하세요. |
| 개미가 격자 경계에 도달해 정지했습니다 | 경계 처리가 "끊김"이라 가장자리에서 멈춘 것입니다. 격자를 키우거나 "이어짐"으로 바꾸세요. |
| 조건과 행동 사이에 `->`를 넣어 주세요 | `(조건) -> (명령)` 형식이 아닙니다. |
| 조건 '…' 형식이 잘못되었습니다 | 위치 번호는 1~9, 상태는 A–Z 또는 0–9만 쓸 수 있습니다. (예: `ant_cell_1=A`) |
| 알 수 없는 행동 '…' | 명령 철자나 형식을 확인하세요. (`straight` / `left` / `right` / `flip` / `paint` / `paint_prev`) |
| 이동 거리는 1~1000이어야 합니다 | `_n`의 `n` 범위를 확인하세요. |
| 기존 규칙과 조건이 중복되었습니다 | 조건이 같은 규칙이 두 번 있습니다. 하나만 남기세요. |
| 색 설정 / `setbg` / `setstart`가 중복되었습니다 | 같은 명령을 두 번 썼습니다. |
| `setbg` / `setstart` 형식이 잘못되었습니다 | 기호는 A–Z 또는 0–9 하나입니다. (예: `setbg A`) |

### 6. 팁

- 규칙이 위에서부터 차례로 검사되므로, `&`로 조건을 많이 건 규칙을 위에, 단순한 규칙을 아래에 쓰세요.
- 모든 상태에 대해 규칙이 하나는 있어야 개미가 멈추지 않습니다. 새 상태를 `paint`로 만들었다면 그 상태의 규칙도 함께 쓰세요.
- 직진만 하는 규칙이 섞이면 개미가 경계에 금방 닿습니다. 처음에는 "이어짐"으로 두고 관찰하면 편합니다.
- 규칙이 어떻게 동작하는지 헷갈리면 **한 단계** 버튼으로 하나씩 실행해 보세요.

본 이용허락에 따른 허용 범위에서는 상업적 이용을 허용하지 않습니다.

상업적 이용에는 영리 목적의 판매, 유료 제공, 상업적 서비스에의 통합 및 그 밖에 주된 목적이 상업적 이익이나 금전적 보상을 얻는 이용이 포함될 수 있습니다.

상업적 이용을 원하는 경우 사전에 저작권자에게 별도 허가를 받아야 합니다. 상업적 이용 여부가 불분명한 경우에는 이용 전에 저작권자에게 문의해야 합니다.

### 제6조 권리 및 책임

본 이용허락은 저작권자가 보유한 권리를 넘어서는 권리를 부여하지 않습니다.

프로그램은 별도의 명시적 보증 없이 제공됩니다. 관련 법령상 배제할 수 없는 보증이나 책임은 이 조항으로 배제되지 않습니다.

이용자는 프로그램을 이용하거나 수정본을 배포할 때 적용되는 법령과 제3자의 권리를 준수해야 합니다.

### 제7조 이용허락 위반

이용자가 본 조건을 위반한 경우, 저작권자는 관련 법령에 따라 이용 중단이나 권리 침해에 대한 구제 조치를 요청할 수 있습니다.

### 제8조 AI 도구 활용 안내

본 프로젝트의 개발 및 코드 개선 과정에서 AI 도구가 활용되었습니다.

AI 도구가 제안한 코드와 설명이 포함될 수 있으며, 본 안내문은 AI가 생성한 모든 부분에 대해 저작권자가 독점적인 권리를 보유한다고 주장하는 의미가 아닙니다. 각 부분의 권리 관계는 실제 창작적 기여와 적용되는 법령 및 제3자 라이선스에 따라 판단됩니다.

### 제9조 조건의 해석

본 조건은 대한민국 법령을 기준으로 해석합니다. 구체적인 분쟁의 해결은 적용되는 법령에 따릅니다.
